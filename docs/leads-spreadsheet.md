# 診断・問い合わせリードのスプレッドシート管理（2026-08-25）

診断を受けてくれた人と、問い合わせをくれた人を、Googleスプレッドシートで一括管理できるようにした。

## できること

日次cron（毎朝5時JST）が動くたびに、Supabaseの`contact_submissions`の中身をスプレッドシートに丸ごと書き出す。シートは2タブ構成:

| タブ | 中身 | 使い方 |
|---|---|---|
| **リード一覧** | メールアドレスで名寄せした「人」の一覧 | 普段見るのはこっち。誰が診断を完了して、どのタイプだったかが1人1行 |
| **履歴ログ** | 全イベントの時系列ログ | いつ何が起きたかを追いたいとき |

### リード一覧の列

初回接触 / 最終接触 / お名前 / メールアドレス / 会社名 / 診断（完了・開始のみ） / 診断タイプ / 想定職種 / レポートDL / 問い合わせ / 接触回数 / テスト

- **診断**: 「完了」=11問終わった、「開始のみ」=名前とメールを入れたが結果まで到達していない（＝離脱ポイントが見える）
- **テスト**: ミネさん本人（mine@potentialight.com）や`@example.com`などの動作確認用は「テスト」と入る。並べ替え・フィルタで畳める

同期のたびに**全件を上書き**する（追記ではない）。シートに手で書いた列は消えるので、メモを残したい場合は右側に別の列を足すのではなく、別シートを作って`VLOOKUP`で引くこと。

## セットアップ（初回だけ・人の作業）

1. Googleスプレッドシートを新規作成する（名前は「Ocean Quest リード管理」など）
2. 右上「共有」から、**GA4連携で使っているサービスアカウントのアドレス**に**編集者**権限を渡す
   - アドレスが分からない場合は、Vercelの環境変数`GOOGLE_CLIENT_EMAIL`（または`GOOGLE_SERVICE_ACCOUNT_JSON`の中の`client_email`）を見る
   - `...@....iam.gserviceaccount.com` という形のアドレス
3. スプレッドシートのURLからIDを取る
   ```
   https://docs.google.com/spreadsheets/d/【ここがID】/edit
   ```
4. Vercelの環境変数に `LEADS_SHEET_ID` を追加して、3のIDを入れる
5. 再デプロイ（環境変数は再デプロイしないと反映されない）

## 動作確認 / 手動で同期する

翌朝のcronを待たずに今すぐ流したいときは、この1本を叩く。

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://ocean-quest.jp/api/admin/leads-sync
```

- 成功すると `{"ok":true,"people":6,"events":10,...}` が返る
- `LEADS_SHEET_ID`未設定なら、共有すべきサービスアカウントのアドレスを`shareWith`で返すので、それを2の共有先に使えばよい
- 共有権限が足りないときはGoogle側のエラーがそのまま返る（403なら共有のし忘れ）

`CRON_SECRET`はVercelの環境変数と同じ値。**このエンドポイントは個人情報を扱うのでシークレット必須**。公開URLやトークン付きURLは意図的に作っていない（スプレッドシートに書き込む「押し出し」方式にして、外から取れる口を増やさないため）。

## 注意

- Supabaseの読み取りは5分キャッシュが効く。診断を受けた直後に同期しても出ないことがあるので、その場合は5分待つ
- 同期はGA4/Search Consoleと同じサービスアカウントを使い回している。新しい認証情報は増やしていない
- `LEADS_SHEET_ID`が未設定のあいだ、cronはこのステップをスキップするだけで他の処理は普通に動く

## 実装

- `lib/leads.ts` — 種別の判定（問い合わせ / 診断スタート / 診断を受けました / レポートDL）と、人物への名寄せ。**通知メールと同じ判定を使っている**ので、メールの見た目とシートの「種別」は必ず一致する
- `lib/sheets.ts` — Google Sheets APIへの書き込み（タブが無ければ自動作成）
- `app/api/admin/leads-sync/route.ts` — 手動トリガー
- `app/api/cron/daily-maintenance/route.ts` — 日次cronへの組み込み
